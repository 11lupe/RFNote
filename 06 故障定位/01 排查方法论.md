# 排查方法论

> 故障定位的目标不是「让它过」，而是**找到可解释、可复现、可预防的根因**。过是结果，不是证据。
> 本文给通用四步法与记录模板；具体链路见 [发射链路故障](<02 发射链路故障.md>)、[接收链路故障](<03 接收链路故障.md>)、[仪表与链路故障](<04 仪表与链路故障.md>)。

## 1. 先把「失败」定义清楚

一个可排查的失败至少要有：

| 要素 | 例子 | 缺了会怎样 |
|---|---|---|
| 指标/判据 | ACLR 偏 3 dB、REFSENS 差 4 dB | 不知道查什么 |
| 条件 | band n78、100 MHz、QPSK、最大功率 | 无法复现 |
| 范围 | 某工位/某信道/某机型 | 无法二分 |
| 证据 | 原始 trace、配置、日志、校准版本 | 只能猜 |
| 时间/环境 | 温度、电源、固件、脚本版本 | 无法排除漂移 |

「测试挂了」不是失败描述；「n78、100 MHz、PC3、最大功率、ACLR 在 +10 MHz 偏 3 dB，其他信道正常」才是。

## 2. 证据优先级

从高到低：

1. **可复现的原始数据**：trace、IQ、吞吐序列、功率计读数。
2. **配置快照**：仪表设置、DUT 状态、校准文件、脚本版本。
3. **日志**：仪表错误队列、DUT radio/kernel log、测试框架日志。
4. **时间线**：什么时候开始、改了什么、换过什么。
5. **口述/记忆**：只能作线索，不能作结论。

先存证，再动手；很多问题在重启/重连后就再也复现不了。

## 3. 四步法

### 第一步：复现与定范围

- 同一条件重复 3 次：稳定失败、偶发、还是只出现一次？
- 换信道/band/带宽/功率/工位/机型：哪些组合失败？
- 失败是「绝对值错」还是「相对某基线漂」？
- 记录环境：温度、电源、线缆、开关矩阵路径。

目标：把「全部失败」缩成「某条件下失败」。

### 第二步：建基线

- 用 golden sample / 已知良品跑同一条件。
- 用同一仪表、同一线缆、同一校准文件。
- 基线通过 → 更像 DUT；基线也失败 → 更像系统。

没有基线，就无法判断「这个值本来就该是多少」。

### 第三步：分层隔离

按四条链路拆：

| 层 | 问题 | 隔离动作 |
|---|---|---|
| 信号 | 线缆/开关/衰减/夹具/仪表端口 | 换线、换端口、直连、功率计校 |
| 控制 | SCPI 同步/触发/超时/状态 | 手动操作仪表对比、读错误队列 |
| DUT | 测试态/band/功率/天线/电源 | 换 DUT、回读状态、换测试态 |
| 环境 | 温度/干扰/屏蔽/供电 | 换屏蔽箱、电池供电、关共存 |

原则：**从最便宜、最可替换的层开始**；线缆/端口通常比 DUT 好换。

### 第四步：二分与替换

- 二分：把链路从中间断开，测前半段/后半段；把频段/信道分成两半。
- 替换：已知好线换可疑线、已知好仪表换可疑仪表、已知好 DUT 换可疑 DUT。
- 一次只改一个变量；改完立即复测，记录结果。
- 若替换后故障消失，再把旧件换回，确认故障复现（排除巧合）。

## 4. 常见反模式

| 反模式 | 为什么错 | 替代 |
|---|---|---|
| 一上来改脚本/加补偿 | 可能掩盖系统误差 | 先校路径、看原始数据 |
| 同时换多个件 | 不知道谁修好的 | 单变量替换 |
| 只看最终值 | 丢失波形/配置/日志 | 存 trace + 配置快照 |
| 用「重跑就过了」结案 | 偶发根因仍在 | 记录发生率与条件 |
| 把环境干扰当 DUT 杂散 | 误判设计 | 断开 DUT/换屏蔽验证 |
| 用更高功率「压过去」 | 掩盖线性度/校准问题 | 查为什么不够 |

## 5. 典型决策树

```text
FAIL
├─ 所有 band/信道/工位都失败
│  ├─ golden sample 也失败 → 仪表/校准/线缆/触发
│  └─ golden sample 通过   → 公共 DUT 配置/测试态/电源
├─ 只有某 band/信道失败
│  ├─ 校准表该频点异常 → 重校
│  ├─ 滤波器/匹配/本振   → 对比同平台、看 S 参数
│  └─ 干扰/谐波           → 换频、屏蔽、关共存
├─ 只有某工位失败
│  ├─ 路径损耗/开关路径   → 逐路校准
│  └─ 夹具/屏蔽/接地       → 换夹具、查漏
└─ 偶发
   ├─ 连接/接触            → 换线/接头、看日志
   ├─ 温度/电源            → 监控、稳压
   └─ 软件状态             → 复位、看门狗、复现
```

## 6. 记录模板

```text
标题：<一句话现象>
环境：机型/固件、仪表/固件、脚本版本、工位、温度/电源
条件：band/信道/带宽/RB/调制/功率/天线
现象：指标、期望、实测、偏差、复现率
证据：trace/日志/截图/配置/校准文件路径
排查：按时间线列「假设 → 动作 → 结果」
根因：<机制，不是「仪表坏了」>
修复：<改了什么>
验证：<改前复现/改后通过/回归范围>
预防：<校准/检查/自动化/文档>
```

## 7. 闭环

- **修复**：改硬件/校准/脚本/配置，明确版本。
- **验证**：原条件复现消失；相邻条件/回归不引入新问题。
- **预防**：加开班校验、加 guard band、加日志、加自动化检查。
- **沉淀**：案例写进 [典型案例](<05 典型案例.md>)，更新检查清单。
