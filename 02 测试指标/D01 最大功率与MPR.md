## 1. 定义与判决公式（背这一段就够）

MOP：在**指定信道 / 带宽 / RB 分配 / 调制**下，UE 能发出的**发射期平均功率**上限能力。

```
上限 = 名义功率 + 容差 − MPR − A-MPR
下限 = 名义功率 − 容差
```

**MPR 只松上限，不抬下限。** 这句话能挡掉一半追问：它解释了"为什么读数低于名义值仍然 PASS"。

- 名义功率由 Power Class 决定：PC3 = 23 dBm，PC2 = 26 dBm（n41/n77/n78/n79 等），PC1.5 = 29 dBm。
- 容差：FR1 PC3 常见 ±2 dB（LTE 亦为 2 dB 量级，个别 band 不同）。
- 测的是 **ON 期平均功率**，不是峰值、不是整帧平均、不是"仪表上一次留下的读数"。
- 数字只作量级参考：判定以 **TS 36.101 §6.2.2 / TS 38.101-1 §6.2A.2**（限值）与 **36.521-1/38.521-1 对应测试条件表**为准，平台再叠客户系数。

回答口径：**"以规范表为准，平台配的是 X，客户在这个基础上放宽/收紧了 Y。"** 不背数字，说清来源。

## 2. 测试条件矩阵：每个维度为什么必须覆盖

| 维度 | 取值 | 为什么是它（常被追问的一句） |
|---|---|---|
| 信道 | 低 / 中 / 高 | 前端滤波器与走线插损随频率变化，**带边最容易掉功率** |
| 带宽 | 最宽 + 最窄 | 功率谱密度、PA 工作点不同；宽带可分配 RB 更多 |
| RB 分配 | 1RB@最低 / 1RB@最高 / 满 RB | 部分 RB 是 **MPR 的触发条件**；满 RB 才是"最大能力" |
| 调制 | 最低阶 + 最高阶（QPSK…256QAM） | 高阶调制 PAPR 高，**MPR 更大、线性度要求更高** |
| 天线端口 | 每根 Tx 分别测 | 多天线机型各通道插损不同，不能只测主集 |
| 功率控制态 | 必须确认在最大档 | 最常见的假失败：以为拉满了，其实没有 |

→ 这就是"15 个 band 怎么膨胀成几十上百个 case"的算法：不是拍脑袋列 40 项，是**维度笛卡尔积 + 等价类裁剪**（同一 band 内中信道可抽检、窄带宽可只测 1RB）。

## 3. MPR：为什么允许"不达标"（这题答不出等于没做过功率测试）

**物理原因**：高阶调制、窄 RB 分配时信号 PAPR 大。PA 若仍顶到 23 dBm 会进入压缩区 → ACLR 与 EVM 一起崩。规范于是给你一个合法选择：**降功率，换频谱质量**。

| 调制 | MPR 量级 | 典型触发 |
|---|---|---|
| π/2 BPSK、QPSK | 0 dB | — |
| 16QAM | 1 dB | 部分 RB |
| 64QAM | 2 dB | 部分 RB / 带边 |
| 256QAM | 2–3 dB | 宽带边缘 RB |

- **A-MPR**：在 MPR 之外、按 band + 网络配置（如 LTE 的 NS_xx）再允许的回退，常见于带内/邻带保护场景。被追问"MPR 和 A-MPR 什么区别"时：MPR 看**调制与 RB**，A-MPR 看**频段与部署**。
- 表版本很重要：不同 release 的 MPR 表不一样，**代码里要能读出用的是哪版表**。

**判决伪代码（注意别写成 abs）**：

```python
def judge_mop(meas, nominal, tol, mpr, ampr):
    upper = nominal + tol - mpr - ampr
    lower = nominal - tol
    return lower <= meas <= upper, (lower, upper)

# 反例：abs(meas - nominal) <= tol
# —— 在 MPR 生效的配置下会把合法值判成 FAIL，这是"成功率虚低"的常见来源
```

**算一遍**：64QAM、部分 RB、MPR=2 dB、名义 23、容差 2 → 判区间 [21, 23] dBm。实测 21.5 → **PASS**。若你按 21–25 判，这台机器会被误判；若你按 [21,25] 判又放过了一批本该 FAIL 的。

| MPR 表 | 例 2 dB（64QAM） | 合法回退 | 3GPP 表 | 见 §3 | 用错→误判 | 谁是表的 owner？ |

### 参考电平的坑（顺手纠一个错）

- **设得过高**（远高于实际输入）→ 仪表加大衰减、量程变粗 → **噪声底抬高** → **小信号测不准**（关闭功率、杂散、最小功率）；大信号基本不受影响。
- **设得过低**（低于实际输入）→ 前端过载 / ADC 削顶 → **压缩** → 读数偏低、频谱再生（ACLR/SEM 跟着一起变差）。

一句话记：**高了伤小信号，低了伤大信号。**

> 常见误区是把它记反成"太高→压缩、太低→削顶"；方向以 §2 的机制为准。

## 5. 测量骨架：SCPI 同步怎么写才不被问倒

```python
def measure_mop(inst, cfg):
    inst.write('*CLS')                              # 1. 清状态与错误队列
    inst.write(cfg.band_channel_bw)                 # 2. 制式/band/信道/带宽
    inst.write(cfg.rb_allocation)                   #    RB 数与位置
    inst.write(cfg.ref_level)                       #    参考电平
    inst.write(cfg.trigger_source)                  # 3. 触发源
    inst.write('INIT')                              # 4. 启动测量
    if inst.query('*OPC?').strip() != '1':          #    同步：完成才往下走
        raise InstrumentTimeout(cfg)
    val = float(inst.query('FETCh:...:POWer?'))     # 5. 取数
    err = inst.query('SYST:ERR?').strip()           # 6. 每次必查错误队列
    return Result(value=val, raw=cfg, error=err)    # 7. 原始读数 + 配置快照一起存
```

四个必须能解释的点：

1. **为什么不能发完命令立刻读？** 仪表内部是流水线 + 状态机，`write` 只保证命令进了缓冲区，不保证测量完成。盲读拿到的是上一次结果或 0。
2. **`*OPC?` 在做什么？** 挂到 OPC 位上的操作全部完成后才返回 `1`；`INIT` 之后立刻查，是最常用的同步写法。
3. **`SYST:ERR?` 为什么必查？** 非法头、参数越界、量程溢出都不抛异常，只进队列。不查 = 失败无据可查，也无法证明"不是脚本的锅"。
4. **为什么要存配置快照？** 只存一个功率值，失败后无法复现。快照 = 信道/RB/调制/参考电平/校准值/时间戳/仪表固件版本。

> CMW500 / SP9500 的私有命令头随固件版本变化，以 SCPI 手册为准；这里只固定 488.2 通用部分，差异收敛在驱动层（B4 那一课再展开）。

## 6. 失败归因：四步法 + 一个可以脱口而出的案例

按顺序查，命中即停：

1. **同位置换 golden sample** —— 仍然低 → 测量系统；通过 → DUT 问题。
2. **换通道**（线缆 / 接头 / 工位）—— 有变化 → 硬件链路；不变 → 脚本或仪表设置。
3. **看原始数据** —— 窗口位置、波形形状、参考电平、平均次数是否合理；不合理 → 测量配置错。
4. **查基准** —— 校准是否过期、校准平面对不对、最近有没有换过线。

**叙事模板（数字替换为实际值）**：

> 有个工位整批偏低 1.2 dB，脚本没改过。我先换 golden sample，还是低，说明不是产品问题；再把同一根线换到隔壁工位，偏差跟着线走；最后一查是接头磨损，换线后偏差回到 0.1 dB 以内。所以我的结论不是"我觉得是线缆"，而是"换线复测后偏差从 1.2 dB 降到 0.1 dB，定位在接头"。

**结论必须落到可执行动作 + 可复现证据**，这是「会用」与「知道边界」的分界线。

## 8. 参考答案与评分点

**1.** 上限 = 名义 + 容差 − MPR（− A-MPR），下限 = 名义 − 容差；MPR 只松上限。*评分点*：说出"只松上限"得核心分；补出 A-MPR 或"降功率换 ACLR/EVM"得满分。

**2.** **PASS**。判区间 [21, 23]，21.5 落在区间内。*评分点*：先算 MPR 再判；若答 FAIL 说明还在用 `abs(meas−nominal)≤tol` 的写法，这是要改的第一处代码。

**3.** 高 → 衰减大、噪声底高 → 关闭功率/杂散/最小功率这类**小信号**测不准；低 → 过载削顶 → 最大功率/ACLR/SEM 这类**大信号**失真。记："高了伤小信号，低了伤大信号"。

**4.** 换 golden sample → 换线/换工位 → 查校准与参考电平。*评分点*：结论必须带数字对比（1.2 dB → 0.1 dB）和动作（换线复测），只说"查一下线"不得分。

**5.** 分层：`规范限值层` → `客户配置层（系数或覆盖值）` → `判定层`。代码只读配置，不硬编码；规范表不改，客户要求记在配置与测试计划里。*评分点*：说出"可配置、可追溯、能回答这个数从哪来"。

**6.** 两个理由：① 部分 RB 是 MPR 的**触发条件**，只有测它才知道 DUT 在"合法回退"下是否真的回退到位，这是规范强制的覆盖；② 满 RB 只覆盖"最大能力"，覆盖不到带边 + 高阶调制这种最容易暴露 PA 线性度与滤波问题的组合。*评分点*：把"覆盖"和"MPR 触发"分开讲。

**建议：6 题中至少答对 5 题，且第 2、3 题必对**；答不上就回看 §1–§3。
