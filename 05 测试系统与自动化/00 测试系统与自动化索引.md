# 测试系统与自动化索引

> 共 **4** 篇。定位：把仪表、DUT、夹具、校准和测试序列组成**可重复、可追溯**的测试系统。
> 边界：仪表本身怎么用看 [仪表与设备](<../04 仪表与设备/00 仪表与设备索引.md>)；指标定义与限值看 [测试指标](<../02 测试指标/00 测试指标索引.md>) 与 [规范与标准](<../03 规范与标准/00 规范与标准索引.md>)。本域只讲「系统怎么搭、怎么控、怎么保证数据可信」。

## 体系

| 层 | 文档 | 回答的问题 |
|---|---|---|
| 架构 | [测试系统架构](<01 测试系统架构.md>) | 控制面、信号面、DUT 面、数据面怎么分层；信令与非信令怎么选 |
| 控制 | [SCPI 与仪表驱动](<02 SCPI与仪表驱动.md>) | 命令发下去后，怎么知道测量真的完成了；超时、状态、二进制数据怎么处理 |
| DUT | [DUT 控制与测试模式](<03 DUT控制与测试模式.md>) | 怎么让手机进测试态、锁 band、控功率、取日志，以及怎么避免把 DUT 控死 |
| 校准 | [路径损耗与夹具校准](<04 路径损耗与夹具校准.md>) | 仪表端口到 DUT 端口之间到底损耗多少；夹具、开关矩阵、接头怎么校 |

后续可扩展：测试序列与判定、数据记录与报告、并行测试与资源调度、异常恢复与看门狗。先不建空文档，内容成熟再加。

## 阅读路径

- **第一次搭台**：架构 → 路径损耗 → SCPI → DUT 控制。先把参考平面和校准做对，再谈脚本。
- **脚本能跑但数据不可信**：先看 [路径损耗与夹具校准](<04 路径损耗与夹具校准.md>) §5 的复核清单，再看 [SCPI 与仪表驱动](<02 SCPI与仪表驱动.md>) §5 的同步问题。
- **换仪表/换平台**：架构 §3 的信令 vs 非信令、§6 的选型清单；单台仪表细节进 [04 仪表与设备](<../04 仪表与设备/00 仪表与设备索引.md>)。
- **指标本身怎么判**：回 [02 测试指标](<../02 测试指标/00 测试指标索引.md>)；限值条款回 [3GPP 检索索引](<../03 规范与标准/3GPP/00 3GPP检索索引.md>) §4。

## 维护

- 一篇只讲一个系统层；跨层的结论用链接，不复制正文。
- 命令、寄存器、厂商工具名只作示例，不写内网地址、账号、测试机名与客户名。
- 具体型号能力以厂家当前固件/选件为准；本域不写死「某仪表一定支持某功能」。
- 新增文档后更新本页「共 N 篇」、[README](<../README.md>) 目录表与总篇数，跑 `python tools/repo/check.py`。
