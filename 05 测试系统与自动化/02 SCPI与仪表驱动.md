# SCPI 与仪表驱动

> SCPI 是「命令 + 查询」的文本协议，但自动化里最容易错的不是命令拼写，而是**同步**：命令返回 ≠ 测量完成，查询返回 ≠ 数据是这一次的。
> 本文讲 VISA 会话、命令/查询、完成判定、二进制数据、超时与重连、驱动分层。仪表功能本身见 [射频常用仪表](<../04 仪表与设备/01 射频常用仪表.md>)。

## 1. 连接与资源字符串

| 传输 | 典型资源串 | 说明 |
|---|---|---|
| TCP/IP（VXI-11） | `TCPIP0::<ip>::inst0::INSTR` | 常用；端口/防火墙要通 |
| TCP/IP（raw socket） | `TCPIP0::<ip>::<port>::SOCKET` | 裸 socket，速度快，无 VISA 发现 |
| GPIB | `GPIB0::<addr>::INSTR` | 老仪表多；需要 GPIB 卡/驱动 |
| USB | `USB0::<vid>::<pid>::<serial>::INSTR` | 即插即用，注意 USB 稳定性 |
| 串口 | `ASRL<com>::INSTR` | 少见于仪表，多用于 DUT/电源 |

原则：

- 资源串、IP、端口写进配置文件，不写死在代码和文档里；文档用 `<ip>` 占位。
- 连接前先 `ping`/`*IDN?`，确认是目标仪表，不是同网段另一台。
- 会话建立后设超时；不同操作（配置/测量/取 trace）用不同超时。
- 关闭时先复位/本地化，再关会话，避免仪表停在远程状态。

## 2. 命令与查询

```text
写：  :CONF:POW:ACQ:MOD 1
读：  :CONF:POW:ACQ:MOD?
查询：:MEAS:POW?      ← 可能触发一次测量并返回结果
```

- 命令大小写不敏感，但参数单位/格式敏感；不确定时先 `*RST` 后按手册顺序配。
- 查询必须在写之后、且仪表处理完；连续发多条命令时，注意输入缓冲区/队列上限。
- 不要用「读一个查询」来清错误；用 `SYST:ERR?` 逐条读到 0。
- 命令树因厂商/型号不同；驱动层要隔离差异，测试层只调语义方法（`set_band`、`measure_power`）。

## 3. 完成判定：`*OPC?` 不是万能的

| 机制 | 作用 | 注意 |
|---|---|---|
| `*OPC?` | 前面的操作完成后返回 `1` | 只保证命令处理完，不一定保证测量/平均完成 |
| `*OPC` | 完成后置 OPC 位 | 配合状态寄存器/Service Request |
| `*WAI` | 等前面的操作完成 | 阻塞，长测量会卡死；慎用 |
| `*CLS` | 清状态/错误队列 | 开始前清，避免旧错误 |
| `SYST:ERR?` | 读错误队列 | 配置后必查，别只看返回值 |
| `STAT:OPER?` / `STAT:QUES?` | 操作/可疑状态 | 测量完成、过载、未锁定常在这里 |
| `*STB?` | 状态字节 | 配合 SRE/ESE 使能 |

典型顺序：

```text
*CLS
配置...
*OPC?            ← 等配置生效
发起测量
*OPC?            ← 等测量完成（若仪表支持）
取结果
SYST:ERR?
```

如果仪表把「测量完成」放在操作状态寄存器或专用事件位，就以状态位为准；`*OPC?` 只作为兜底。长平均/扫描时用轮询状态位 + 超时，不要固定 `sleep`。

## 4. 触发与多仪表同步

- 明确触发源：立即（IMM）、总线（BUS）、外部（EXT）、定时（TIM）。
- 谁产生触发、谁接收触发、触发后哪台仪表开始测量，要画时序。
- 多仪表测同一 DUT 时，尽量用同一参考时钟/外部触发；没有就固定软件顺序，并留 settle。
- 切换开关矩阵后，先等继电器稳定，再触发测量；机械开关寿命与抖动要记录。
- 并行测试时，仪表共享会引入状态污染；每段测量前后复位/清状态。

## 5. 二进制数据与 trace

频谱仪/示波器的波形/频谱常用二进制块：

```text
#<n><len><payload>
```

- `<n>` 是长度字段的位数，`<len>` 是 payload 字节数；先读头再读数据。
- 用 VISA 的 `read_raw`/`query_binary_values`，不要按文本 `read` 再解析。
- 注意字节序（大端/小端）、数据类型（int16/float32）、是否含包头。
- 大数据量会超时；分块读或加大超时，并校验长度。
- 存原始 trace 时同时存：中心频率、span、RBW、检波器、平均次数、参考电平。

## 6. 超时、重试与重连

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 查询超时 | 仪表在忙/触发没来/命令错 | 查状态、补触发、加大超时 |
| 读到上一次结果 | 没等本次完成/缓冲区残留 | `*CLS`、读空、用 OPC/状态位 |
| 连接断开 | 网线/USB/仪表重启 | 健康检查、重连、重跑当前步骤 |
| 命令队列溢出 | 连续写太快 | 分批、查询握手、加流控 |
| 结果全 0/不变 | 远程模式没进/选件没开 | 查 `*IDN?`、模式、选件、错误队列 |

重试原则：只重试**幂等**步骤；测量失败先保存现场（截图/日志/错误队列），再重试；重试次数和原因要记录，不能静默吞掉。

## 7. 驱动分层

```text
测试用例 / 序列
   └── 语义 API：set_band(), measure_aclr(), get_throughput()
         └── 仪表驱动：命令映射、单位、状态、错误处理
               └── 传输层：VISA/socket、超时、重连、日志
```

- 测试层不拼 SCPI 字符串；换仪表只换驱动。
- 驱动暴露能力查询（支持哪些 band/带宽/选件），不支持的配置提前报错。
- 每次测量记录：仪表型号/固件、资源串、关键设置、原始结果、错误队列。
- 驱动要有 `reset()`/`preset()`，但不要在测量中途随意复位，避免状态丢失。

## 8. 最小 Python 骨架

```python
import pyvisa

rm = pyvisa.ResourceManager()
inst = rm.open_resource("TCPIP0::<ip>::inst0::INSTR")
inst.timeout = 10_000
inst.write_termination = "\n"
inst.read_termination = "\n"

print(inst.query("*IDN?").strip())
inst.write("*CLS")
inst.write(":CONF:POW:ACQ:MOD 1")
inst.query("*OPC?")
inst.write(":INIT:IMM")
inst.query("*OPC?")
print(inst.query(":MEAS:POW?").strip())
print(inst.query("SYST:ERR?").strip())
inst.close()
```

示例只表达顺序，命令名以实际仪表手册为准。

## 9. 检查清单

- [ ] 资源串/超时来自配置，不写死。
- [ ] 连接后 `*IDN?` 校验型号。
- [ ] 配置后查错误队列，关键配置回读。
- [ ] 测量完成有状态位/OPC/事件依据，不靠固定延时。
- [ ] 二进制块按头解析，长度/字节序正确。
- [ ] 超时/断线有分级处理，失败保存现场。
- [ ] 每次结果带仪表设置与校准版本。
