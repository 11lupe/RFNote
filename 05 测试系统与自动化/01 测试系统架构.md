# 测试系统架构

> 一个射频自动化测试系统，本质是四条链路的组合：**信号链、控制链、DUT 链、数据链**。脚本只是控制链的一部分；数据不可信，通常不是脚本语法错，而是另外三条链没对齐。
> 本文给搭台、扩展、换平台的架构骨架；仪表本身见 [射频常用仪表](<../04 仪表与设备/01 射频常用仪表.md>)，校准细节见 [路径损耗与夹具校准](<04 路径损耗与夹具校准.md>)。

## 1. 四条链路

```text
┌──────────────────────────── 控制面 ────────────────────────────┐
│  PC / 测试框架 ── VISA/驱动 ──→ 综测仪、信号源、频谱仪、开关矩阵 │
│        │                                                        │
│        └── ADB / AT / QMI / Diag ──→ DUT                        │
└─────────────────────────────────────────────────────────────────┘
┌──────────────────────────── 信号面 ────────────────────────────┐
│  仪表端口 ── 线缆 ── 衰减/滤波 ── 开关/合路 ── 夹具 ── DUT 天线口 │
│        ▲                                              │          │
│        └──────────── 上行/反馈（功率、频谱、吞吐）─────┘          │
└─────────────────────────────────────────────────────────────────┘
┌──────────────────────────── 数据面 ────────────────────────────┐
│  测量结果、原始 trace、DUT 日志、配置快照、校准文件、判定记录    │
└─────────────────────────────────────────────────────────────────┘
```

| 面 | 主要组成 | 典型问题 |
|---|---|---|
| 信号面 | 仪表、线缆、衰减器、滤波器、开关矩阵、合路器、夹具、暗室 | 损耗没校、隔离不够、接头坏、屏蔽差 |
| 控制面 | PC、VISA/驱动、测试序列、DUT 控制通道 | 命令没同步、状态没清、超时、重连 |
| DUT 面 | 手机、测试态、band/功率/天线配置、电源 | 没进测试态、配置没生效、电量/温度漂移 |
| 数据面 | 结果、trace、日志、配置、校准、判定 | 只存最终值、无法复现、缺原始证据 |

四条链路任何一条断了，现象都可能是「测试失败」，所以排障要先分层，不要一上来改脚本。

## 2. 信号链的参考平面

限值定义在 **DUT 天线端口**。仪表端口到 DUT 端口之间的所有损耗/增益，都必须校准并补偿：

```text
仪表端口 ── 线缆 A ── 开关 ── 线缆 B ── 夹具/耦合器 ── DUT 端口
           \________ 路径损耗 L(f) ________/
```

- 传导测试：用功率计/信号源测每一路的 `L(f)`，按频率存校准表。
- OTA 测试：校准到暗室参考点，再换算 EIRP/EIS。
- 开关矩阵：每条路径单独校，不能用一个平均损耗代替。
- 合路器/功分器：插入损耗与隔离都要算；双向链路要分别校。
- 衰减器：既保护仪表，也改善匹配；但会降低信噪比，位置要算进链路预算。

## 3. 信令 vs 非信令

| 维度 | 信令（callbox） | 非信令（test mode） |
|---|---|---|
| 建链 | 模拟小区，DUT 正常注册 | 厂商测试模式/专用命令 |
| 真实性 | 接近现网，能测吞吐、切换、CA | 只测射频指标，快 |
| 速度 | 慢（建链、状态迁移） | 快（直接进测试态） |
| 稳定性 | 受协议状态、网络配置影响 | 受厂商工具/权限/固件影响 |
| 适用 | 吞吐、端到端、认证类 | 研发、产线、射频指标 |
| 风险 | 建链失败难定位 | 测试态可能与现网行为不同 |

选择原则：

- 指标测试（功率、EVM、ACLR、灵敏度）优先非信令，速度快、变量少；
- 吞吐、CA/EN-DC、切换、协议行为必须信令；
- 认证/运营商准入按测试计划要求，不能随意替换；
- 同一项目里两种模式混用时，要固定 DUT 状态和校准，避免结果不可比。

## 4. 控制链的时序

一条测量不是「发命令 → 读结果」，而是：

```text
配置 → 触发 → 等待稳定 → 开窗测量 → 等完成 → 取数 → 判定 → 存证
```

关键点：

- **配置生效**要确认：仪表返回错误队列为空、DUT 状态回读一致。
- **触发**要明确：立即触发、外部触发、总线触发，谁触发谁。
- **稳定**要留时间：PA 热漂移、AGC 收敛、电源上电、开关切换都需要 settle。
- **完成**要确认：`*OPC?`/状态位/事件寄存器，不能只靠 `sleep`。
- **取数**要区分：标量结果、数组 trace、二进制块，字节序和包头要处理。
- **判定**要可追溯：原始值、配置、校准版本、时间、工位一起存。

## 5. 夹具、屏蔽与接地

- 夹具的第一目标是**可重复**，不是「能固定住手机」。
- 屏蔽箱要处理缝隙、线缆入口、滤波器面板；屏蔽度不够时，环境干扰会伪装成 DUT 杂散。
- 接地要单点/低阻抗，避免地环路；USB、电源、网线都是干扰入口。
- 天线耦合式夹具要控制位置、极化、距离；每次换手机/换夹具都要复核耦合损耗。
- 大功率测试要加衰减器/隔离器，确认仪表输入不被烧；DC block 防直流偏置。
- 高压/高温/电池测试要有急停与温度保护，脚本不能绕过硬件保护。

## 6. 常见架构模式

| 模式 | 结构 | 优点 | 代价 |
|---|---|---|---|
| 单仪表直连 | 一台综测仪 ↔ 一个 DUT | 简单、损耗少 | 吞吐低、难并行 |
| 开关矩阵 | 多仪表/多端口经矩阵切换 | 灵活、可扩展 | 路径损耗/隔离/校准复杂 |
| 多工位并行 | 每工位一套仪表或分区 | 产能高 | 资源调度、互不干扰难 |
| 仪表共享 | 多 DUT 分时共享一台仪表 | 成本低 | 切换/排队/状态污染 |
| 暗室 OTA | 转台/探头/暗室 | 整机真实 | 慢、校准复杂、成本高 |

选择时先算清楚：**测试时间、并行数、仪表数量、路径损耗、隔离度、预算**，不要先写脚本再补架构。

## 7. 上电/联调清单

1. 断电检查线缆、接头、衰减器方向、直流偏置。
2. 仪表自检/校准状态确认，固件与选件记录。
3. 测路径损耗，写入校准表，覆盖所有 band/信道/端口。
4. 用 golden sample 跑一遍已知结果，确认系统基线。
5. 确认 DUT 能进测试态、能回读状态、能重启恢复。
6. 跑一条完整序列：配置 → 测量 → 判定 → 存证 → 复位。
7. 拔插/重启/断网各一次，确认异常恢复。
8. 记录系统版本：脚本、仪表固件、校准文件、夹具编号。

## 8. 常见错误

| 现象 | 架构层根因 | 处理 |
|---|---|---|
| 换工位结果差 2 dB | 路径损耗/夹具没单独校 | 每工位、每端口独立校准 |
| 某 band 噪声大 | 开关矩阵隔离不够/线缆屏蔽差 | 查隔离、换屏蔽线、加滤波 |
| 测试越跑越慢 | 超时/重试堆积、仪表状态未清 | 看门狗、状态复位、超时分级 |
| 并行时互相干扰 | 仪表共享/电源/时钟耦合 | 分区、独立电源、错峰触发 |
| 结果无法复现 | 配置/校准/温度没记录 | 存配置快照与环境信息 |
