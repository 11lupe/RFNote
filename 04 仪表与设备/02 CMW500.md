# R&S CMW500 综测仪

> 定位：2G/3G/4G 与 WLAN/BT/GNSS 的主力综测仪。一台机器同时是「假基站 + 信号源 + 分析仪」，研发、产线、认证预演都用它。
> 边界：5G NR 的同类工作一般交给 CMX500，本文只讲 CMW500 本身。测量方法看 [测量基础与校准](<../02 测试指标/01 测量基础与校准.md>)，指标定义看 [测试指标索引](<../02 测试指标/00 测试指标索引.md>)。
> 文中数字均为量级参考，以厂家数据表 + 当前固件为准；命令名是结构示意，落地前用仪表帮助核对。

## 1. 它解决什么问题

频谱仪 + 信号源 + 脚本也能测，但测不了「真实通信状态」：DUT 得自己注册、自己调度、自己发。CMW500 的价值就在内置协议栈——把 DUT 拉进指定状态，然后在同一个射频口、同一套时钟下完成发射与接收测量。

| 用法 | 谁在控制 DUT | 节拍 | 适合 |
|---|---|---|---|
| 信令（Signaling） | 仪表协议栈 | 慢，秒级/项 | 研发验证、认证预演、吞吐与灵敏度 |
| 非信令（GPRF） | 外部：ADB / AT / 厂商工具 | 快，百毫秒级 | 产线、校准、快速回归 |
| ARB 波形回放 | 仪表播波形 | 快 | RX 阻塞、互调、ACS、干扰场景复现 |

一句话：**信令测「它对不对」，非信令测「它快不快」**。研发阶段用信令，产线用非信令，两者结果对不上时先怀疑 DUT 状态不同，而不是仪表不准。

## 2. 端口、参考与触发

| 项 | 说明 | 注意 |
|---|---|---|
| RF1 / RF2 | 两路独立收发，可各自出/收 | 软件里的端口路径要和物理接线一致；路径损耗按端口分别存 |
| RF3 / RF4 | 扩展口，需硬件与授权 | 多 DUT、4×4 MIMO 扩展时才用得上 |
| 10 MHz 参考 | 输入 / 输出 | 多仪表系统共用参考，否则各表频率不同源 |
| 触发 | Trigger in/out、Marker | 时隙与子帧对齐靠它，别指望自由运行 |
| LAN / GPIB / USB | 远程控制 | 优先 LAN（VXI-11 / HiSLIP）；USB 适合单机调试 |
| SIM 参数 | 内置 SIM 模拟或插卡 | IMSI / Ki / OPc / APN 错一个，注册就上不去 |

两个容易忽略的点：

- **端口路径损耗表**是分开存的。只校了 RF1，换到 RF2 测，全项会整体偏。
- **参考与触发线**要和频谱仪、信号源共享。不共享时，频率误差、EVM、时间对齐都会「各自为政」。

## 3. 能力与选件

| 维度 | 内容 | 怎么确认 |
|---|---|---|
| 制式 | GSM/(E)GPRS、WCDMA/HSPA、LTE/LTE-A、cdma2000、TD-SCDMA、WLAN、Bluetooth、GNSS | 选件表 + 实测建链 |
| 带宽 | LTE 单载波 20 MHz，CA 聚合更宽；WLAN 宽带宽需宽带选件 | 选件表 |
| 端口 / MIMO | 基础 2×2，4×4 需扩展口与授权 | 端口清单 |
| 衰落 | 内置衰落选件，用于灵敏度与移动性场景 | 选件表 |
| 波形 | ARB 播放厂家波形或自建波形 | 波形库 |
| 频率上限 | 按射频前端选件，常见 3.3 GHz 与 6 GHz 两档 | 机型标签 |

选件确认只有两个可靠办法：前面板 `Setup → Instrument Setup → Options`，或远程读 `*OPT?`。**买硬件不等于有功能**：信令、测量、波形、衰落、GNSS 是分别授权的，报 `unsupported` 先去查这一层，别怀疑 DUT。

## 4. 信令模式：把 DUT 拉进状态

### 4.1 建链流程（以 LTE 为例）

1. 仪表侧配小区：频段、带宽、功率档、PLMN、APN、承载类型。
2. 准备 SIM：插卡或启用内置 SIM 模拟，卡参数与 DUT 要求一致。
3. DUT 开机 → 搜网 → Attach → RRC 连接 → 默认承载建立。
4. 切到目标状态：最大功率档、最低功率档、指定 MCS、指定 RB 分配。
5. 启动 Multi-Evaluation 采集，`FETCh` 取结果，一轮拿全功率、SEM、ACLR、EVM、频率误差、OBW。

### 4.2 建链失败怎么查

| 现象 | 先查 |
|---|---|
| 一直 Searching | 频段/带宽组合是否支持、PLMN、天线口、线损是否过大 |
| 注册被拒 | SIM 参数（Ki/OPc）、鉴权算法、APN、DUT 是否锁网 |
| 注册上但无数据 | 默认承载、IP 分配、DUT 数据开关 |
| 时通时断 | 功率档、线损、屏蔽、DUT 温升与降功率 |

排查顺序固定：**射频通路（线损/接头）→ SIM 与网络参数 → DUT 状态 → 仪表选件**。反过来查，最浪费时间。

## 5. 非信令（GPRF）：产线的主力

GPRF 把仪表拆成两半：generator 给 DUT 喂信号，analyzer 收 DUT 的信号，与协议栈无关。

- 流程：DUT 进工厂/校准模式 → 设频点与功率档 → 仪表设频率、电平、触发、测量长度 → 采集 → 换算。
- 前提：**DUT 状态由外部保证**。状态没锁住，结果不可复现，而且看起来「每次都不一样」。
- 适合：产线、校准、快速回归。
- 不适合：需要真实调度与吞吐统计的场景（灵敏度、移动性、切换）。

## 6. 发射测量：一次采集拿全

| 项 | 关键设置 | 常见问题 |
|---|---|---|
| 功率 | 测量长度、门控、平均 | 门控压在开关瞬态上，读数偏低 |
| SEM | 偏移点、测量带宽、检波器 | 环境干扰被当成带外发射 |
| ACLR | 信道滤波器、平均次数 | 平均不足，结果抖动大 |
| OBW | 99% 功率口径 | 与频谱仪的积分带宽设置不一致 |
| EVM | 均衡、同步、子帧对齐 | 未对齐时 EVM 虚高 |
| 频率误差 | 解调参考、平均 | 参考时钟没共享 |

三个口径问题必须先说清楚，否则数据没法比：

- **平均 vs 峰值**：限值看的是哪种，脚本就要取哪种。
- **测量长度**：太短统计不足，太长节拍崩；以能覆盖一个完整帧结构为准。
- **结果分位**：有的项看 95% 分位，有的看最大，别一律取平均。

## 7. 接收与吞吐

| 做法 | 怎么测 | 代价 |
|---|---|---|
| 信令 + BLER/吞吐 | 仪表调度、统计误块率或吞吐曲线 | 慢，样本量大才可信 |
| 非信令 + DUT 自报 | DUT 报 BER/PER，仪表只提供电平 | 快，但依赖 DUT 自测口径 |

灵敏度类测试的成本几乎全在**统计样本量**上：要判 1% 量级的误块率，样本不够时置信区间会宽到没有意义。产线的做法通常是单点灵敏度 + 抽测曲线，研发才跑完整曲线。

干扰与衰落场景（阻塞、ACS、互调）优先用 ARB 波形 + 内置衰落，复现性比外接干扰源好。

## 8. SCPI 骨架

```text
# 树形结构示意（命令名随固件调整，落地前用仪表帮助核对）
<制式>                          # LTE / WCDMA / GSM / WLAN ...
  CONFigure:<制式>:SIGN:...      # 信令：小区、网络、承载
  CONFigure:<制式>:MEAS:...      # 测量：射频设置、触发、长度、平均
  INITiate:<制式>:MEAS:...       # 启动测量
  FETCh:<制式>:MEAS:...          # 取结果，不重测
  READ:<制式>:MEAS:...           # 重测并取结果
GPRF                            # 非信令：信号源 + 分析仪
  SOURce:GPRF:GENerator:...      # 发生器
  CONFigure / SENSe:GPRF:...     # 分析仪
```

- 通用命令：`*RST`、`*CLS`、`*IDN?`、`*OPT?`、`*OPC?`、`SYST:ERR?`。
- **取结果优先 `FETCh`**：Multi-Evaluation 一次采集多项，逐项重测既慢又不一致。
- 同步用 `INIT` + `*OPC?`，或 `*OPC` + SRQ。`*OPC?` 只保证命令执行完，不保证测量收敛，收敛要看测量状态。

```python
import pyvisa

rm = pyvisa.ResourceManager()
cmw = rm.open_resource("TCPIP0::192.0.2.10::inst0::INSTR")
cmw.timeout = 30_000

print(cmw.query("*IDN?").strip())
print(cmw.query("*OPT?").strip())        # 先确认选件，再决定跑哪些用例
cmw.write("*CLS")

# ... 配置小区 / 测量 ...

cmw.write("INITiate:LTE:MEASurement:MEValuation")
cmw.query("*OPC?")
err = cmw.query("SYST:ERR?").strip()
if not err.startswith("0"):
    raise RuntimeError(err)
```

## 9. 十个坑

1. **选件没买**：报不支持是能力问题，不是 DUT 故障。
2. **路径损耗没按端口校**：全项整体偏移，且换口才暴露。
3. **触发没对齐子帧**：EVM、ACLR 偏高，重测又不复现。
4. **采集太短 / 平均不足**：偶发 FAIL，复测通过。
5. **参考电平过高**：底噪抬升，小功率项根本测不到。
6. **信令下没切到目标状态**：测到的是「能通」，不是「最好」或「最差」。
7. **非信令下 DUT 状态没锁**：结果不可复现，归因全错。
8. **温度漂移**：仪表与 DUT 都漂，整批同向偏移先怀疑环境。
9. **屏蔽不到位**：杂散与灵敏度假失败，换台机器就好。
10. **固件升级后命令行为变化**：昨天能跑的脚本今天报错，版本要锁。

## 10. 验收与维护

- [ ] 端口回损与接头状态：力矩、磨损、转接头混用。
- [ ] 功率精度与频率准确度：用功率计与参考源交叉验证。
- [ ] 残余 EVM 与相噪：这是你能测到的下限。
- [ ] 触发与参考共享：多仪表系统联调一次。
- [ ] 选件表与固件版本：写进测试报告，和结果一起归档。
- [ ] 校准到期日：过期先校准，别在数据上找原因。
