# 星河亮点 SP9500 综测仪

> 定位：国产 5G NR 综测仪，面向 FR1 终端的研发与产线测试，覆盖 NR（SA / NSA）与 LTE anchor，替代或补齐 CMW500 / UXM 的位置。
> 边界：这类设备型号与固件迭代快，本文只写「怎么用、怎么验、哪里踩坑」。支持的 band、带宽、MIMO 层数、GCF/PTCRB 覆盖以厂家当前规格书与选件表为准，不要照搬本文的示例配置。
> 本文不写具体性能数字：国产仪表的指标随版本变化大，一律以出厂数据表 + 到货实测为准。

## 1. 它是什么，不是什么

- 是：一台能做**信令建链 + 非信令快速测量**的 NR 综测仪，形态与用法对标 CMW500 / UXM：一台机器同时当假基站、信号源和接收测量单元。
- 不是：CMW500 的兼容替代。命令树、选件体系、自动化接口都是自成一套，**已有脚本不能直接移植**，必须经过驱动层适配。
- 常见角色：产线主测、研发回归、国产化替代项目里的第二套台架；也常与 CMW500 并存，用来交叉验证。

## 2. 与主流机型怎么分工

| 维度 | SP9500 | CMW500 | UXM |
|---|---|---|---|
| 制式覆盖 | NR FR1 + LTE anchor（NSA）为主 | 2G/3G/4G + WLAN/BT/GNSS | 2G–5G，NR 更深 |
| 命令体系 | 自家 SCPI / 厂商 API | R&S SCPI | Keysight SCPI |
| 协议栈成熟度 | 需按目标芯片与固件验证互操作 | 成熟，覆盖广 | 成熟，NR 场景强 |
| GCF / PTCRB | 以认可清单为准，覆盖面通常小于两家大厂 | 覆盖广 | 覆盖广 |
| 文档与生态 | 手册、示例、第三方 ATE 适配需逐个确认 | 生态最全 | 生态全 |
| 典型位置 | 产线、国产化项目、第二台架 | 研发主力、产线 | 研发主力 |

选型结论通常是：**认证与互操作风险高的项目仍以大厂为主台，SP9500 做产线或补充台架**；纯产线、DUT 芯片固定、指标稳定的场景，SP9500 的性价比才成立。这个判断要在项目早期做，别等台架搭完。

## 3. 到货先核对的清单

| 项 | 为什么重要 | 怎么确认 |
|---|---|---|
| RAT 授权 | NR SA / NSA / LTE 可能分别授权 | 选件表 + 实际建链各跑一次 |
| band 与带宽 | 目标 band（n41/n78/n79 等）与最大带宽决定能测什么 | 逐 band 建链，别只看规格书 |
| 端口与 MIMO | 2×2 / 4×4、TX/RX 是否可并行 | 端口清单 + 并行测量实测 |
| 衰落 / AWGN | 灵敏度与移动性场景要用 | 选件表 + 波形库 |
| 远程接口 | LAN？VXI-11 / raw socket？USB？ | 用 `*IDN?` 从自动化侧连一次 |
| 参考与触发 | 多仪表共时钟 | 后面板确认 10 MHz 与 Trigger 口 |
| 固件版本 | 决定命令行为与已知问题 | 记录版本号，写进测试报告 |

## 4. 建链：SA 与 NSA 两条路

### 4.1 SA

1. 仪表配 NR 小区：band、带宽、SCS、功率档、PLMN。
2. DUT 注册 → RRC → PDU 会话建立。
3. 切目标状态：功率档、MCS、RB 分配。
4. 采集发射项，再做接收项。

### 4.2 NSA（LTE anchor + NR 辅小区）

比 SA 多三步，也最容易出错：

1. 先建 LTE anchor 小区，DUT 在 LTE 上注册并建立承载。
2. 配置 NR 辅小区（频段、带宽、功率），触发 SCG 添加。
3. 确认 DUT 确实进了双连接状态，再测 NR 项。

常见失败：anchor 与 NR 的频段组合不支持、两者功率档不一致、SCG 添加超时、DUT 侧双连接开关没开。**测 NR 项之前先确认「现在真的是双连接」**，否则测到的是 LTE 或空闲态。

## 5. 非信令与校准模式

- 非信令下仪表只做「发 + 收」，DUT 由 ADB/AT/厂商工具拉进工厂模式。
- 产线节拍主要靠它；前提同样是 DUT 状态被锁死。
- 校准模式（如果有）要单独确认授权与命令集，别假设和测量模式同一套接口。

## 6. 自动化接入

命令树与 CMW500 不同，接入原则只有一条：**把差异关在驱动层**。

- 通用命令仍然通用：`*IDN?`、`*OPT?`、`*CLS`、`*OPC?`、`SYST:ERR?`。先跑通这几个，再接私有命令。
- 私有命令随固件版本变化，全部收在 driver 里；用例只调 `set_power()`、`measure_evm()` 这类语义接口。
- 资源名与超时按实际接口写，别照抄 CMW500 的 `TCPIP0::...::inst0::INSTR`；不确定就用 `pyvisa.ResourceManager().list_resources()` 列出来再选。
- 多仪表系统共享 10 MHz 参考与触发，否则频率与时间对不齐。

```python
import pyvisa

rm = pyvisa.ResourceManager()
print(rm.list_resources())                       # 先看这台机器实际暴露了什么

inst = rm.open_resource("<资源名，从上面列表里选>")
inst.timeout = 30_000
print(inst.query("*IDN?").strip())
print(inst.query("*OPT?").strip())
inst.write("*CLS")
# ... 建链与测量 ...
err = inst.query("SYST:ERR?").strip()
if not err.startswith("0"):
    raise RuntimeError(err)
```

## 7. 导入新机 / 新固件前的验证

固定四步，缺一步就会在项目中期返工：

1. **静态**：频率准确度、功率精度、残余 EVM、相噪、带宽——用参考仪表或功率计交叉验证。
2. **比对**：同一台 DUT、同一状态，与 CMW500/UXM/FSW 各测一遍，差异要能解释（口径不同 vs 真的偏）。
3. **重复性**：同一测量连跑 20–30 次，看标准差；产线关心的是 σ，不是单次最好值。
4. **互操作矩阵**：目标芯片型号 × DUT 固件 × 仪表固件，各跑一次建链。矩阵里任何一格失败，都要在排产前解决。

## 8. 坑

1. **拿 CMW500 脚本直接套**：命令不存在或语义不同，表现为「连上了但测不出数」。
2. **固件与文档不同步**：手册写的命令在新固件里改了，先看仪表帮助再照手册。
3. **GCF 覆盖没核对**：认证场景直接不可用，越晚发现越贵。
4. **NSA 下 anchor 与 NR 状态混淆**：测 NR 项时其实还在 LTE 单连接。
5. **状态机等待时间照抄大厂经验**：国产协议栈节拍不同，超时设短了就偶发失败。
6. **路径损耗表没按端口建**：换口后整批偏移。
7. **升级后旧配置/旧波形不兼容**：升级前导出配置，升级后回归一遍。
8. **第三方 ATE 适配成本被低估**：产线软件对接要单独排期。
