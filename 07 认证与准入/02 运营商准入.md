# 运营商准入

> 运营商准入是「产品能不能进这家运营商的网、能不能上架销售」的商业与技术门槛。它通常以 GCF/PTCRB 为基础，再叠加运营商自己的 IOT、现网、性能与定制要求。不同运营商差异很大，本文给通用框架与证据清单。

## 1. 准入的层级

| 层级 | 目的 | 典型内容 |
|---|---|---|
| 白卡/入库测试 | 技术准入 | RF、协议、RRM、IOT、OTA、SAR/EMC 报告 |
| 现网验证 | 真网可用 | 路测、切换、语音、数据、漫游 |
| 定制验收 | 符合运营商产品规范 | UI、预置、频段、双卡、VoLTE/VoNR |
| 持续监控 | 上市后质量 | 现网 KPI、投诉、回归 |

先确认目标层级，再决定测试范围；不要用「实验室全过」代替「现网可用」。

## 2. 测试范围

- **RF/射频**：功率、频谱、调制、接收、CA/MIMO；
- **协议/RRM**：接入、切换、重选、移动性、双连接；
- **IOT**：与运营商现网设备（多家设备商）的组合；
- **OTA**：EIS/TIS、天线性能、手握/头手；
- **法规相关**：SAR、EMC、安全（通常复用法规报告）；
- **用户体验**：语音质量、数据吞吐、时延、功耗、热；
- **定制**：频段组合、双卡、VoLTE/VoNR、紧急呼叫、漫游。

## 3. 典型流程

```text
商务/技术对接
  → 获取测试规范与用例清单
  → 样机与软件版本冻结
  → 预测试（实验室/现网）
  → 正式测试与问题单（issue tracker）
  → 回归与闭环
  → 报告提交/评审
  → 入库/销售许可
  → 上市后监控
```

运营商通常有明确的问题分级（阻塞/严重/一般），阻塞项未闭环不会放行。

## 4. 交付物

| 交付物 | 内容 |
|---|---|
| 测试报告 | 用例、配置、结果、失败项、证据 |
| IOT 矩阵 | 网络设备/版本/band/功能组合 |
| 现网记录 | 路线、站点、KPI、异常 |
| 问题闭环 | 问题单、根因、修复、回归 |
| 一致性声明 | 软件/硬件版本、校准状态 |
| 法规报告 | SAR/EMC/安全（按需） |

## 5. 与 GCF/PTCRB 的关系

- GCF/PTCRB 是「行业信用」，运营商通常采信但不完全替代；
- 运营商可能要求额外 band/CA、现网 IOT、定制功能；
- 运营商的用例版本可能落后或超前于 GCF；
- 同一产品在不同运营商处的测试范围可能不同。

## 6. 样机与配置

- 使用与量产一致的硬件、天线、外壳、电池；
- 软件版本冻结，测试态与量产态差异要记录；
- 校准数据、路径损耗、测试夹具可追溯；
- 每个 band/CA/功能组合都要有代表性样机；
- 准备备用机与恢复方案，避免测试中断。

## 7. 常见失败

- 只在实验室过，现网切换/重选失败；
- IOT 只测一家设备商，现网多厂商不兼容；
- VoLTE/VoNR 边界（弱覆盖、切换、紧急呼叫）未覆盖；
- 双卡/漫游/频段组合漏测；
- 功耗/热导致降频，吞吐不达标；
- 问题单闭环证据不足，评审被退回。

## 8. 准备清单

- [ ] 目标运营商与准入层级已确认。
- [ ] 测试规范/用例版本已获取并评审。
- [ ] 样机/软件/校准与量产一致。
- [ ] 预测试问题已闭环。
- [ ] IOT 矩阵覆盖主流设备商。
- [ ] 现网路线与 KPI 基线已准备。
- [ ] 报告模板与问题单格式符合要求。
