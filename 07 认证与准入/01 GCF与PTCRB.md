# GCF 与 PTCRB

> GCF 和 PTCRB 是两套主流的终端互操作/一致性认证体系。它们不是法规，但运营商通常把「通过 GCF/PTCRB」作为入库前提。本文讲流程与证据，具体用例、费用与成员规则以官方最新文件为准。

## 1. 它们是什么

| 项目 | GCF | PTCRB |
|---|---|---|
| 全称 | Global Certification Forum | PCS Type Certification Review Board |
| 性质 | 行业认证论坛 | 北美运营商主导的认证体系 |
| 主要覆盖 | GSM/WCDMA/LTE/NR 终端一致性 | 北美市场终端一致性/互操作 |
| 采信方 | 全球多家运营商 | 北美运营商 |
| 与 3GPP 关系 | 以 3GPP 测试规范为基础 | 同样以 3GPP 测试规范为基础 |

两者都依赖 3GPP 的测试规范（如 51.010-1、34.121-1、36.521-1、38.521-1），但**用例集合、版本、豁免与运营商附加要求不同**。通过一个不等于自动通过另一个。

## 2. 认证对象

- 终端（手机、模组、CPE、穿戴）；
- 平台/芯片方案（平台认证可被终端复用，但有条件）；
- 特定功能集（band、CA、VoLTE、VoNR、LAA 等）。

认证按「产品 + 功能集」发证，功能增减可能触发补充测试。

## 3. 典型流程

```text
确定目标市场与运营商
  → 选功能集/band/CA 组合
  → 生成测试计划（work item / test case 列表）
  → 选择经认可的实验室与测试平台
  → 样机准备（软件版本、校准、测试态）
  → 预测试 / 问题定位
  → 正式执行并生成报告
  → 提交审核（GCF/PTCRB）
  → 发证/列名
  → 变更管理（PCN/改版/补测）
```

## 4. 关键输入

| 输入 | 说明 |
|---|---|
| 功能集 | band、带宽、CA、MIMO、VoLTE/VoNR、NSA/SA |
| 测试计划 | 由认证体系/运营商确认的用例清单 |
| 测试平台 | 经平台验证的综测仪/系统模拟器 |
| 实验室 | 具备相应认可资质 |
| 样机 | 与量产一致的硬件/软件/校准 |
| 报告 | 完整配置、结果、失败项与豁免 |

## 5. 测试内容（按大类）

- **RF 一致性**：功率、频谱、调制质量、接收指标；
- **协议一致性**：NAS/RRC/MAC/RLC/PDCP；
- **RRM**：切换、重选、测量、移动性；
- **SIM/USIM/NA**：卡接口与网络接入；
- **互操作（IOT）**：与网络设备/运营商网络的组合；
- **特定功能**：CA、MIMO、VoLTE/VoNR、LAA、NTN 等。

具体用例编号以 GCF/PTCRB 的测试计划为准，不要拿 3GPP 条款号直接当用例号。

## 6. 实验室与平台

- 实验室需具备相应认可范围；
- 测试平台需通过平台验证（platform validation），否则结果不被采信；
- 同一用例在不同平台/版本上可能有差异，报告要写清平台与版本；
- 仪表校准、路径损耗、测试态配置都要可追溯。

## 7. 变更管理

以下变更通常触发评估/补测：

- 硬件改版（天线、PA、滤波器、PCB）；
- 软件版本升级（协议栈、RF 校准）；
- 新增 band/CA/功能；
- 关键器件换料（PA、开关、双工器）。

提前准备 PCN（Product Change Notification）与差异分析，能减少重复认证。

## 8. 准备清单

- [ ] 目标市场/运营商清单已确认。
- [ ] 功能集与 band/CA 矩阵已冻结。
- [ ] 测试计划版本与用例清单已确认。
- [ ] 实验室资质与平台验证状态已确认。
- [ ] 样机软件/硬件/校准与量产一致。
- [ ] 预测试失败项已闭环。
- [ ] 报告模板与证据链（配置/日志/照片）已准备。

## 9. 常见坑

- 用「工程样机」送测，量产一致性对不上；
- 功能集漏报，上市后补测；
- 用例版本与测试计划不一致；
- 测试平台未验证，报告不被采信；
- 测试态软件与量产软件不同，复现困难；
- 忽略运营商附加要求（如特定 IOT、现网验证）。
