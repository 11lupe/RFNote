# 测试项矩阵

> 矩阵的作用不是「把所有测试都列一遍」，而是把目标市场、制式、band/CA、功能、样品与工位映射成一份可执行、可裁剪、可追溯的计划。先定范围，再排优先级。

## 1. 矩阵维度

| 维度 | 取值示例 | 说明 |
|---|---|---|
| 市场 | 中国/欧盟/北美/日韩 | 决定法规与运营商清单 |
| 认证体系 | 法规、GCF、PTCRB、运营商 | 决定用例来源 |
| 制式 | GSM/WCDMA/LTE/NR | 决定 3GPP 规范与仪表 |
| Band/带宽 | B1/B3/n41… | 决定射频前端与校准 |
| CA/MIMO | 组合、层数、UL CA | 决定测试复杂度 |
| 功能 | VoLTE/VoNR、双卡、漫游、LAA | 决定协议/IOT 范围 |
| 样品 | EVT/DVT/PVT/量产 | 决定测试深度与样本量 |
| 工位 | 传导/OTA/现网 | 决定夹具与环境 |

## 3. 排优先级

1. **阻塞项**：法规、SAR、EMC、GCF/PTCRB 关键用例——不过就不能卖。
2. **覆盖项**：RF/RRM/协议全 band 扫描——决定现网体验。
3. **体验项**：OTA、吞吐、功耗、热——决定用户感知。
4. **定制项**：运营商/客户特定功能——按合同。

资源有限时，先保证阻塞项与主流 band/CA 组合，再用风险抽样覆盖边缘组合。

## 4. 执行顺序

```text
法规预扫（EMC/射频/SAR）
  → RF 传导（TX/RX）
  → RRM/协议
  → CA/MIMO
  → OTA
  → 运营商 IOT/现网
  → 回归与报告
```

预扫放最前，因为天线/外壳/功率变更会导致后面全部重测。

## 5. 每条用例要写清

- 样机：型号、序列号、硬件版本、软件版本；
- 配置：band、带宽、RB、MCS、天线、功率；
- 环境：温度、夹具、线缆、校准日期；
- 判据：规范号 + 节号/表格，或运营商用例号；
- 证据：截图、日志、原始数据、失败现象；
- 结论：通过/失败/豁免（豁免要有依据）。

## 6. 裁剪与风险

- 相同射频前端/相同 band 的机型可共用部分结果，但要证明「射频路径一致」；
- 平台认证可复用，但天线/外壳/校准变化要补测；
- 边缘 band/CA 组合按出货量与风险抽样；
- 任何裁剪都要有书面依据，不能口头豁免。

## 7. 常见错误

- 矩阵只列测试项，不列配置与判据；
- 不同步软件版本，失败无法复现；
- 只测实验室，不测现网；
- 忽略 SAR/EMC 对天线与外壳的约束；
- 认证后再改硬件，触发全量重测。
